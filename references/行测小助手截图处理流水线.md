# 行测小助手截图 → 分析 → 入库三步流水线

## 触发条件

用户从「行测小助手」App 发送截图，截图包含：
- 已作答的题目（用户答案 + 正确答案 + 答题用时）
- 用户可能不说话（截图即消息），也可能说「怎么算的」「入库」

## 三阶段

### 阶段1：截图发来 → 分析

1. vision_analyze 读取截图，提取：
   - 题型名称（题头绿色标签）
   - 题干数据 + 选项
   - 用户答案（红色） + 正确答案（绿色）
   - 答题用时（判断是公式不熟还是计算偏差）

2. 计算正确答案，验证是否与 App 标注一致

3. 推断用户错因：
   - 不是只看用户选了什么——反向计算什么运算路径会得出那个数字
   - 只写「这个数字 + 对应选项」的路径，不在选项中的不写

### 阶段2：用户说「怎么算的」→ 分步拆解

格式固定：

**公式：** {公式名}

| 步骤 | 动作 | 结果 |
|:----:|:----|:----:|
| ① | {公式代入} | {中间值} |
| ② | {继续运算} | {中间值} |
| ③ | {最终运算} | **{正确答案}** ✅ |

**你的错因：**
- {错误路径 A} → {结果} → 接近选项 X
- {错误路径 B} → {结果} → 你选了 D ❌

**考场估算技巧：**
{替代精确计算的快速方法}

### 阶段3：用户说「入库」→ 三步操作

1. `cp` 截图到 vault 对应题型/screenshots/
2. `write_file` 创建 错题-{next_id}.md（含完整分析 + 计算步骤 + 错误路径 + 口诀 + 关联错题）
3. `sed` 更新 index.md（last_id++、total++、pending++、追加行）

## 错因推导范例

```
用户选了 D（21.49），正确答案是 B（17.09）

路径分析：
· 部分增量用 606×78.9%=478（忘了÷(1+a)）→ ÷整体现期 2471 → 19.3%（接近 C，不是 D）
· 部分增量同上 478 → ÷整体基期 1564 → 30.6%（不在选项）
· 部分增量算对 267 → ÷整体基期算错 → 多种可能
→ 最接近 D 21.49 的路径是……
```

不写不在选项中的错误路径。只写能推导出「那个数字 + 那个选项」的路径。
